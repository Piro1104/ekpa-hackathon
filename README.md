# ekpa-hackathon
## Πρόβλεψη εξάντλησης

Δύο μέθοδοι, ίδια μορφή εξόδου:

- **rafi** (`rafi/forecast.py`): εξηγήσιμο μοντέλο βήμα-βήμα. Ρυθμός κατανάλωσης από τις
  τελευταίες παραδόσεις, εποχικοί συντελεστές ανά περιοχή × κατηγορία, χειμερινά κλεισίματα,
  νέοι πελάτες από παρόμοιους πελάτες.
- **hybrid** (`rafi/lgbm_engine.py`, προεπιλογή): το rafi συν μια διόρθωση από LightGBM.
  Το μοντέλο εκπαιδεύεται σε παλιά cutoffs («γύρισμα στον χρόνο», μόνο δεδομένα πριν από το
  cutoff) και μαθαίνει τον ρυθμό παραγγελιών του πελάτη. Τελικές ημέρες = 0,55 × LightGBM +
  0,45 × rafi. Τα κλεισίματα μένουν όπως τα βγάζει το rafi. Κάθε γραμμή κρατά την ημερομηνία
  του rafi (`RAFI_DEPLETION_DATE`) και πόσες ημέρες τη μετακίνησε το μοντέλο
  (`MODEL_CORRECTION_DAYS`). Χωρίς `lightgbm` εγκατεστημένο, γυρίζει αυτόματα στο rafi.

```bash
pip install -r requirements.txt
python scripts/make_submission.py              # hybrid
python scripts/make_submission.py --method rafi
python -m rafi.evaluate                        # backtest και ablation
```

Backtest, MAE σε ημέρες (αλήθεια = επόμενη πραγματική παράδοση, προσέγγιση):

| cutoff | rolling180 | rafi | hybrid |
|---|---|---|---|
| 2025-10-31 | 15,4 | 2,81 | **2,69** |
| 2026-06-30 | 16,0 | 6,70 | **4,50** |
| 2025-08-31 | 3,7 | 5,25 | **3,44** |
| 2025-12-31 | 16,0 | 3,81 | **3,80** |
| 2026-02-28 | 7,0 | 6,92 | **5,57** |
| 2026-04-30 | 15,1 | 6,52 | **4,04** |
| 2026-08-01 | 14,3 | 8,07 | **6,08** |
| μέσος όρος | | 5,73 | **4,30** |

Τα δύο πρώτα είναι τα cutoffs του `rafi.evaluate`· τα υπόλοιπα χρησιμοποιήθηκαν για έλεγχο
ότι το hybrid δεν κάνει overfitting σε αυτά. Το hybrid δεν είναι χειρότερο από το rafi σε
κανένα cutoff. Δοκιμάστηκε και απορρίφθηκε: Empirical Bayes / EWMA στον ρυθμό (χειρότερο σε
6 από τα 7 cutoffs).
